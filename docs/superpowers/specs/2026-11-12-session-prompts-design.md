# 会话级系统提示词插件 设计文档

日期：2026-11-12
状态：待批准

## 意图

给 DSH 加一层「可临时挂上去的系统提示词」。人在配置页维护一批提示词
（标题 + 正文），每条可以设「是否生效」和「是否独立在对话框上方」；
在某个会话里勾上就立刻对那个会话生效。

关键约束来自需求确认：注入的是**系统提示词**，模型看得到，
但对话记录里不会多出一条用户消息，也不占对话历史的位。

最常见的用法是临时的、试验性的：这个会话我要它「回答一律用中文」、
「做代码审查时只报问题不给改写建议」。这些约束不该污染别的会话，
也不该在关掉插件后还缠在对话历史里。

## 目标

- 配置页能增删改一批提示词，每条有标题、正文、「生效中」「独立在对话框上方」。
- 生效的提示词出现在输入框上方：独立的逐条常驻成行，其余折叠进一行点开。
- 勾选状态**按会话记**：A 会话勾的不影响 B 会话；关掉页面再打开还在。
- 勾选后从**下一次请求**开始生效，模型可见，对话记录不可见。
- 子 agent 继承父会话的勾选。

## 非目标

- **不做 agent 工具**。允许模型改写自己的系统提示词是一个提示词注入面，
  收益不抵风险。配置和勾选只有人能操作。
- **不在对话记录里留任何痕迹**。不追加事件、不加用户消息、不做可视回执。
  代价是用户无法从对话里回溯「这一轮到底挂没挂提示词」——
  状态只存在于输入框上方那一行。
- **不做按模型/按 provider 分别生效**。要换就换会话。
- **不做提示词的版本历史或撤销**。改错了自己改回来。
- **「独立显示」不做成按会话设置**。它是这条提示词的性格（常驻控件 vs 收进组里），
  跨会话统一。按会话记的只有「勾没勾」。

## 反目标

- 如果插件卸载后会话里还留着注入过的提示词痕迹，算失败。
- 如果勾选一个提示词导致已有对话的 KV cache 之外还改写了历史消息，算失败。
- 如果关掉插件后插件在会话记录里留下了无法解析的事件，算失败
  （这会让人打不开那个会话）。

## 约束

- **会话记录是唯一真相**这条原则在这里必须让步：勾选状态不写会话日志，
  只写插件自己的 JSON。这意味着勾选状态不参与 fork/回放，
  而是靠 `parentSession` 链继承来获得近似行为。这是有意选择，
  因为在会话日志里新增事件类型需要 `ignorable: true`，
  而实时 `Session.append()` 设不了这个标记，会导致会话无法重新打开。
- **空 section 会自动消失**，所以「没勾任何东西」等于「没有这一段」，
  不需要额外的开关去关闭它。
- 改勾选会改变系统提示词前缀，**从改动点往后会失去 provider 侧的 KV cache 复用**。
  这是功能本身的代价，不是实现缺陷，需要在文档里对用户讲清楚。

## 方案（选定的做法）

### 宿主侧：一个 agent 作用域的 section

在 `agent/created` 里为每个 agent 在 `agent.ctx` 上注册一个系统提示词段：

```js
ctx.systemPrompt.section({
  name: 'plugin:session-prompts',
  order: config.order,          // 默认 10150
  text: () => renderFor(agent.id),
})
```

`text` 是函数而不是字符串——每次装配提示词时现算。
所以勾选变化从下一个 step 开始自然生效，不需要任何通知机制，
也不需要碰 `system-prompt` 的重注册路径。

`renderFor(sessionId)`：

1. 取该会话的勾选集合。**缺失**（没有这个 key）就沿
   `sessions.get(id).header.parentSession` 向上走，直到找到有集合的祖先；
   **空数组是一个有效值**，表示"明确一个都不要"，不再向上继承
   （这是子 agent 与 fork 会话拒掉父会话勾选的唯一手段）。
2. 过滤掉已删除的 id、以及 `enabled: false` 的 id——
   **「生效中」是真开关**，关掉即停止注入，不是只影响界面可见性。
3. 按勾选集合里的顺序拼出正文。一个都没剩下则返回 `''`，section 自动消失。

`agent/created` 是串行 awaited 的，注册返回的 disposer 存在插件自己的
effect 里按 agent id 索引——插件卸载时两边都能清干净（`practices.md` 的要求：
`agent.ctx` 上的注册有两个 owner）。

`order` 放插件 Config 里，默认 10150（在第一方指引 10000、
Web surface 10100 之后，persona suffix 10200 之前）。

两个实现上必须做对的地方：

- **`interpolate: false`**。渲染器对 section 文本里未知或畸形 `{{…}}`
  会抛错，而用户手写的正文完全可能包含 `{{` ——一旦抛错，
  那个会话的**每一次请求**都会失败。关掉插值，文本按字面处理。
- **每个 agent 的注册必须幂等**。`SessionStartSource` 包含 `'clear'` 和
  `'compact'`，同一个 scope 里重复注册同名 section 会抛错。
  用 `Map<sessionId, disposer>` 记住，已注册就跳过。

### 宿主侧：数据与路由

插件自己维护一份 JSON（`$DSH_HOME/plugin-data/dsh-session-prompts.json`），
原子写（临时文件 + rename）：

```jsonc
{
  "version": 1,
  "prompts": [
    {
      "id": "p1",
      "title": "回答用中文",
      "text": "…",
      "enabled": true,   // 是否出现在勾选区
      "pinned": false,   // 是否独立成行、不折叠
      "order": 0
    }
  ],
  "ticks": { "<sessionId>": ["p1"] }
}
```

三个精确路由（`ctx.webServer.register`，和 `dsh-connect-workbuddy` 同款）：

| 路由 | 方法 | 作用 |
|---|---|---|
| `/plugins/dsh-session-prompts/state` | GET | 返回 `{ prompts, ticks }`，供两个界面读 |
| `/plugins/dsh-session-prompts/prompts` | POST | 增删改一条提示词（含「生效中」「独立显示」） |
| `/plugins/dsh-session-prompts/tick` | POST | **单条**切换：`{ sessionId, promptId, on }` |

勾选写入刻意做成单条切换而不是整集合覆盖：桌面端和浏览器可能同时开着，
整集合写入会让两边互相覆盖掉对方的勾选。单条切换下并发写不会互盖，
代价是另一页面上看到的可能是旧值——切回该页面时重新拉一次 `state` 解决。

写操作先改内存、再落盘；落盘失败回滚内存并返回错误，界面据此回退勾选框。
**路由只接受本机（loopback）请求**，并校验方法——这是本机界面自己用的，
不是公开 API。远程浏览器打开时勾选区不渲染（GET 403），
这是已知限制，写在 README 里。

### 浏览器侧：两个注册点

**配置页** — `settings.section`，`id: 'session-prompts'`，独立一页。
列表式增删改，每条卡片：标题输入、正文多行输入，下面并排两个开关
「生效中」「独立在对话框上方」，右侧删除。保存走 `POST /prompts`。
样式只用 `--dsw-alias-*` token。

**输入框上方的勾选区** — `conversation.input.dock`，`id: 'session-prompts'`。
组件从标准 prop `sessionId` 拿到当前会话；勾选即 POST，失败回滚并内联报错。

这里分两层渲染，由每条提示词自己的 `pinned`（「独立显示」）决定：

- **独立条目**（`pinned: true`）：每条一行常驻的勾选框 `☑ 标题`，直接排在
  输入框上方，不折叠、不进组。未勾选时仍显示为 `☐ 标题`——否则就没有入口去勾它。
  按 `order` 升序排列。
- **组成条目**（`pinned: false`，默认）：折叠成一行 `提示词 · 已挂 2 条`
  （未挂时为 `提示词`），点击展开为勾选框列表。

独立条目在上，组在下。两层都为空（没有 `enabled: true` 的提示词）时整条不渲染。

「独立显示」是**跨会话**的设置，和「生效中」一样在配置页里管；
「勾没勾」才是按会话记的。

两个界面共享一份客户端缓存（模块级），任一界面写入后通知另一方刷新。
切回某个界面时重新拉一次 `state`，以覆盖另一页面（或另一进程）的写入。

已勾选但被关掉「生效中」的提示词，勾选记录保留、注入立即停止、
在勾选区不可见（状态矩阵里"不出现"那行）。重启该开关后勾选自动恢复。
配置页在关闭一条仍被 N 个会话勾选的提示词时，开关下方提示
「仍有 N 个会话勾选着它」——不阻塞操作，只是别让人意外。

## 界面的具体形态

### 配置页：设置 → 会话提示词

```text
│ 模型        │                                                           │

│ Agent 预设  │  │ 标题  [ 回答一律用中文                         ]    │  │
│ 技能管理    │  │ 正文  ┌─────────────────────────────────────────┐  │  │
│ WorkBuddy   │  │       │ 回答一律用中文，不要中英混杂。           │  │  │
│ 插件市场    │  │       └─────────────────────────────────────────┘  │  │

│             │  └─────────────────────────────────────────────────────┘  │

│             │  └─────────────────────────────────────────────────────┘  │
│             │                                                           │
│             │  ＋ 添加提示词                                            │
└────────────┴───────────────────────────────────────────────────────────┘
```

空状态（一条都没有时，替换掉整个列表区）：

```text
  还没有会话提示词
  添加一条，勾选后即可在对话里生效。
  ＋ 添加提示词
```

- 卡片：`padding: 16px`，内部间距 `12px`，圆角 12px，
  底色 `--dsw-alias-bg-layer-1`，描边 `1px --dsw-alias-border-l1`，
  卡片之间 `12px`。
- 标题与正文前的标签固定 40px、右对齐、`--dsw-alias-label-secondary`。
- 正文用 textarea，起始高度 72px，随内容长高，超过 240px 后内部滚动。
- 开关行：两个 switch 并排，间距 24px，删除是右侧的文字按钮。
- **不变式：`pinned ⇒ enabled`。** 「独立在对话框上方」只在「生效中」打开时可用。
  在「已停用」状态下点它，弹出提示框要求先开启「生效中」，
  不允许直接配置（见下方交互规则）。
- 关闭「生效中」时，若该条正处于「独立在对话框上方」，一并关闭并给了提示。

### 对话框上方：`conversation.input.dock`

三种形态，由每条提示词的「独立在对话框上方」决定：

```text
A. 全部收在组里（默认）

   ⚙  提示词 · 已挂 2 条                                       ▾


B. 部分独立（「回答用中文」「严谨模式」独立，其余收在组里）

   ☑  回答用中文
   ☐  严谨模式
   ⚙  提示词 · 已挂 1 条                                       ▾


C. 全部独立

   ☑  回答用中文
   ☑  代码审查只报问题
   ☐  严谨模式
```

展开组后（上面的独立行保持不变，只在组行下面长出组内条目）：

```text
   ☑  回答用中文
   ☐  严谨模式
   ⚙  提示词 · 已挂 1 条                                       ▴
       ☑  代码审查只报问题
       ☐  严格按现有代码风格
```

尺寸与视觉：

- 每行高度 28px，行间无额外间距；整块左右内边距与输入框卡片对齐。
- 勾选框 16px，与标题间距 8px；标题用 `--dsw-alias-label-primary` 14px。
- 组行左侧一个 16px 图标，右侧 `▾`/`▴` 指示可展开；
  文字用 `--dsw-alias-label-secondary`，悬停后转 `--dsw-alias-label-primary`。
- 组内条目左侧缩进 24px 与组行的图标对齐。
- 整块在 hover 前无背景；hover 行底色 `--dsw-alias-bg-layer-2`。

### 状态矩阵

| 生效中 | 独立显示 | 本会话勾选 | 对话框上方 |
|---|---|---|---|
| 关 | **必为关**（配置层禁止） | 任意 | 不出现（勾选记录保留） |
| 开 | 关 | 未勾 | 收在组内 `☐ 标题`；组折叠时只体现为不计数 |
| 开 | 关 | 已勾 | 收在组内 `☑ 标题`；组折叠时计入「已挂 N 条」 |
| 开 | 开 | 未勾 | 独立一行 `☐ 标题`，常驻 |
| 开 | 开 | 已勾 | 独立一行 `☑ 标题`，常驻 |

因为 `pinned ⇒ enabled`，不存在「关 + 开」这一行。这条不变式在**两处**强制：
配置页的开关交互，以及宿主侧写入校验（`pinned: true` 且 `enabled: false` 的写入直接
拒绝，防止手工改 JSON 或旧数据把它变成非法状态）。

补充规则：

- 「已挂 N 条」**只数组内被勾的条目**，独立条目自己显示了自己，不重复计数。
- 一条「开」的组内提示词都没有时，组行不渲染——即使有独立条目。
- 一行都没有（没有任何「开」的提示词）时，整块不渲染，不留空白。
- 排序：独立条目按 `order` 升序在上，组行在其后；组内条目也按 `order` 升序。
- 展开/折叠状态按会话记，A 会话展开不影响 B 会话。

### 交互与失败

- 勾选/取消：点下立即更新界面，同时 POST；失败则回滚该行并在这行下方内联报错。
- 配置页编辑：防抖 400ms 自动保存；保存失败在卡片顶部内联报错，不丢用户输入。
- 删除提示词：直接删，不二次确认（低频、可重建），但保留其勾选记录，
  重新创建一个同 id 的不会复活——id 不复用。
- 键盘：勾选框可 Tab 聚焦，空格切换；组行可回车展开。

**「独立在对话框上方」的前置校验**

「已停用」状态下「独立在对话框上方」呈灰态（`opacity: 0.4`，`cursor: default`），
点击不切换，而是弹出提示框：

```text
┌─────────────────────────────────────────────┐
│  提示                                       │
│                                             │
│  只有「生效中」的提示词才能独立显示在       │
│  对话框上方。请先开启「生效中」。           │
│                                             │
│  [ 取消 ]              [ 开启并独立显示 ]   │
└─────────────────────────────────────────────┘
```

- 提示框是模态的，Esc 与「取消」都只关闭、不改任何状态。
- 「开启并独立显示」一个动作同时打开两个开关并保存。
- 这个提示只出现在配置页（唯一能配置「独立显示」的地方）。
- 反向规则：**从开着的「生效中」关掉时，若该条正独立显示，一并关掉「独立显示」**，
  并在卡片顶部给一条 4 秒后自动消失的提示
  「已关闭「生效中」，同时取消了独立显示」。不弹模态——这是用户主动做的操作，
  模型已经表达了意图，再拦一次很烦。

## 留给构建者决定的

- 组件内部怎么拆、CSS 怎么写、要不要抽公共 hook。
- JSON 里的 `id` 用递增还是随机串。
- 路由返回的错误体具体字段（只要包含可展示的 message 即可）。
- 配置页「保存」是每次改动自动存还是显式按钮——**我倾向自动存**
  （正文输入用防抖），因为它更像开关不像表单提交；
  但这条不是硬要求。
- 折叠行左侧用什么图标（齿轮、`✎`、还是无图标）。文案用「提示词」，
  需要表达"挂载"语义时可换成「已挂载 N 条」。

## 已知风险

- **顺序敏感**：profile 里已有 `codebuddy-prompt-shim` 挂在
  `system-prompt/assemble` waterfall 上做逐句改写。本插件不碰那个 waterfall，
  但本插件注入的正文会经过它的改写（逐句拆行等）。若注入的正文里有
  触发该改写规则的内容，模型看到的是改写后的版本。这是既有插件的既有行为，
  本设计不处理，但要在 README 里提一句。
- **子 agent 继承依赖 `parentSession` 头字段**。若某个子 agent 创建路径
  不设置这个字段，继承会失效（退化为「不继承」），不会报错。
